What is going on in this demo?

Spot classroom walk · FHRR phasor algebra · every number below is measured on our own data · 2026-07-30

The robot walked one loop of a classroom (2,478 camera frames, ~7×6.5 m). Everything it saw is superimposed into a few single fixed-size vectors — 8,192 complex numbers each. The page you're watching answers "where have I seen this view?", "what did I see there?", and "where were the chairs?" by doing two or three element-wise vector operations per query. No database, no search tree, no memory growth. Milliseconds on a CPU.

The 60-second version

Each vector is a strip holding 8,192 tiny clock hands, each frozen at some angle (a "phasor"). Three operations do all the work:

Bind  ⊗ — add the clock angles, position by position. Like stacking two tinted transparencies: the stack looks like noise, resembling neither input — but nothing is lost.

Bundle  Σ — average many stacks onto one strip, like a multiple-exposure photograph (or many voices on one tape). The strip never gets longer; each recording just gets a little noisier.

Unbind  ⊘ — subtract the angles of a factor you know. Hold up the exact complementary filter and whatever was bound with that factor snaps back into focus; everything else stays noise.

The robot stores what-it-saw ⊗ where-it-was for every moment, all summed into one vector. Unbind by "where" and you get "what"; unbind by "what" and you get "where" — the same memory answers both directions. The catch: recall is approximate, and gets noisier as more items share the vector. That capacity trade is real and you can see it in the demo.

The pipeline, stage by stage

YOLO sees

YOLOv8n runs on every frame: detection boxes (8,878 detections across 2,478 frames) plus one 256-d feature vector per frame. Ordinary computer vision — no VSA yet.

PCA whitening — the step that makes it work at all

Raw YOLO features are nearly parallel: pairwise cosine 0.76–1.00 (mean 0.88), effective rank 8.1 of 256. Every frame "looks like" every other frame, so when hundreds are bundled the shared direction adds up coherently — crosstalk ≈ 365× the signal. Recall is destroyed. Whitening (subtract the mean, decorrelate, rescale) drops off-diagonal similarity to |mean| 0.067 and crosstalk to ≈ 27×; ~90% of the fix is mean-removal alone. Heading recall went 28% → 98% within 20°. This isotropy ⇔ capacity link is the scientific core of the paper — narrowed carefully: prior VSA lineages used random (isotropic-by-construction) atoms, and learned-embedding anisotropy + whitening is established for language embeddings (Mu & Viswanath 2018; Ethayarajh 2019; Su et al. 2021) and learned HRR vectors (Ganesan et al. NeurIPS 2021); the new part is the quantified anisotropy → associative-recall-collapse link on a deployed robot, plus a causal online estimator.

Project to 8,192-d phasors

A fixed random projection lifts the whitened 256-d feature to 8,192 dimensions, then keeps only the angle of each component (unit length). Neighbourhood structure survives; unit length is what makes unbinding an exact inverse.

Encode where / which way / when (FPE)

Continuous quantities become vectors by fractional power encoding: raise a fixed random base vector to a real-valued power (rotate every clock hand proportionally). Lineage: the idea originates with Plate's HRRs, was developed as spatial semantic pointers by Komer et al. (CogSci 2019), and formalized as FPE / Vector Function Architectures by Frady et al. (2021).

ctx_pos(x, y) = Bx^(x/ℓ) ⊗ By^(y/ℓ)     ctx_time(t) = Bt^(t/ℓ)

Nearby places get similar vectors; the length-scale ℓ sets how fast similarity falls off. Heading is special: yaw wraps at ±π, so its base uses integer frequencies (|k| ≤ 3) — ctx(ψ+2π) = ctx(ψ) exactly.

Build the memories

Three per-axis memories (each only discriminates along its own axis):

M_axis = mean_n  content_n ⊗ ctx_axis(n)     axis ∈ {position, heading, time}

Plus the ASTM multi-trace set: class⊗place, class⊗time, place⊗time, and the full class⊗place⊗time event trace — one trace per query shape. Why not one trace for everything? Measured: supplying only one factor to a triple-bound trace ("under-unbinding") attenuates the answer 22× (0.247 vs 0.011). The marginal traces are the high-signal pathways.

Every query = unbind + sweep

residual = M ⊘ (what you know)   →   similarity sweep over (what you don't)

Sweep a dense (x,y) grid for place, 181 angles for heading, the stored codebook for time, the class vocabulary for "what". Ambiguity shows up honestly as a multi-modal heatmap instead of being hidden behind a single best guess.

How to drive the demo

PANELReplay (reverse query) — scrub or auto-play 1,652 held-out frames (the memory stored only every 3rd frame — 826 — so the query view was never stored). Each tick unbinds all three memories by the current frame's content: the heatmap is "where have I seen something like this?" (compare peak marker vs true-pose marker), the polar plot is "facing which way?", the time readout recalls the nearest stored moment (typically 0.2–0.8 s from truth). ~10 ms per query. Two warm blobs = two genuinely similar-looking places — that's the honest answer, not a bug.

PANELClass → where (dropdown) — pick one of 21 classes. Stored frames containing that class are bundled into a probe and unbound from the position memory (~7 ms). A mode select picks the semantic memory: vantage = the observation footprint (where the class was seen from); object = depth-derived object positions (where the class is — chair peak 0.086 m from the largest furniture cluster vs 2.11 m for vantage); now = the λ-decaying working memory (fresh 0.12–0.51 m, honest "forgotten" badge when stale).

PANELClick-to-query (forward) — click anywhere on the map: the point is encoded, unbound, and matched against stored frames → top-k recalled views with thumbnails and detections. Verified: clicking a trajectory point recalled a stored frame 2 cm away.

PANELASTM spatio-temporal queries — give any two of {what, where, when}; the router unbinds the matching trace to decode the third: "where was the chair at t=150?", "when was something at this spot?", "what was here in this window?". Temporal range kernels make a time range cost the same as a time point (closed-form per frequency); small discrete unknowns ("which object moved?") use a fast vocabulary scan.

Language queries — free text as the unbinding key

New (2026-07-30): the demo story now extends to natural language (language_query.py). MiniLM sentence latents are whitened over a ~180-noun vocabulary — the same isotropy medicine, applied to the language modality — projected to phasors, and the memory rebuilt with text-derived class atoms over object-position events. Two mechanisms, tested on 15 paraphrases that were never stored:

  • Soft grounding (text-similarity routing to class atoms): 10/15 top-1, median error 0.11 m.
  • Direct latent unbinding (the free-text latent itself unbinds the memory — no codebook routing): median 0.17 m, 12/15 within 1 m — "luggage"→suitcase 0.03 m, "cold storage for food"→fridge 0.24 m, "cutting tool for paper"→scissors 0.11 m.

Failures are LM-semantic ("something to sit on" spreads over couch/table/chair), not VSA-mechanical — and the two mechanisms fail on different queries, so they are complementary. Figure: outputs/classroom/language_query.png.

Limitations — the 2026-07-30 ledger

The original "what this does not show (yet)" list is mostly resolved. What changed, and what remains:

Since measured/fixed (2026-07-30)

  • Whitening was offline → causal Welford whitening reaches near-oracle recall by the final third (0.146 vs 0.090 m); a frozen calibration lap fails at any K (1.15–1.73 m), EMA is worse, and the design law is store codes as encoded, never re-encode (causal vs final-stats codes stay ~orthogonal, sim 0.29).
  • Frequency bias → it shows up as position error (crosstalk hijacks rare-class peaks), not abstention; log class-weighting fixes it — rare-tercile error 5.15 m → 0.12 m, frequent classes unharmed.
  • Similarities were uncalibrated → per-decode-type null z-scores (z≥3 ≙ sim≈0.0037; 93% confident-correct, 80% abstention precision); AUROC z 0.872 ≈ raw sim 0.878 — within a decode type z is a monotone affine of sim, so its value is the interpretable threshold, not extra discrimination; risk–coverage 42% coverage at 29% selective risk; range-kernel queries need shape-matched nulls.
  • "Which object moved?" unproven → demonstrated synthetically: tv events relocated 1.68 m; gated which_moved ranks tv #1 and measures 1.71 m; control clean (0.38 m); the timeless marginal is bimodal and misleading — the event trace is necessary.
  • Robot pose, not object position → --place-mode object binds to depth-derived object positions; chair peak 0.086 m from the largest furniture cluster (vantage build: 2.11 m).
  • Detector garbage → hygiene filters (--min-class-events, --class-blocklist) drop junk classes at the canonical-stream boundary.

Still open

  • Staged own-data collection with position ground truth (required — school_run1's dataset odometry is diverged).
  • Baselines B–D (temporal graph, LLM-compiler, VLM) + ReMEmbR.
  • Online whitening deployment integration — the eval exists; the pipeline flag does not.
  • Instance identity (tracks as atoms; needs a tracker front-end).
  • Multimodal-time mode-picking (the dominant residual decode error).
  • Real multi-loop robustness — the moved-object result is synthetic; the physical data is still one loop.

Why three codebases tell one story

This demo sits at the junction of three in-house lineages that all speak the same phasor algebra:

  • init-am (the engine behind this page) — episodic memory: bind what-you-saw to where/when, recall either direction.
  • GC-VSA (Krausse, Neftci, Sommer, Renner — NICE 2025, arXiv:2503.08608) — what⊗where⊗when queries, previously synthetic-only; the ASTM panel is those ideas on real robot data.
  • le-marmotte VGPI — localization: lidar positioning in ONE 2048-d vector (~16 KB map), 0.13 m relocalization on this same dataset, with FPGA ports.
One lineage remembers, one queries, one localizes — same bind / bundle / unbind, same fixed-size vectors. VSAs as the algebraic composition layer for embodied spatial cognition: perception, mapping, episodic memory, and localization as operations in a single fixed-dimensional vector space.
