The VSA cognitive-mapping stack — every part, explained

What each file does, when it was added, which memory forgets (only one — on purpose), and the measured numbers behind it all. Companion to the live demo at localhost:8020.

First, the decay question — does the map forget item locations?

No. Every memory that stores where items are is permanent. The decay factor λ exists in exactly one optional, separate vector — the working memory M_now — built only if you run build_now. Its job is the one question a permanent memory cannot answer well: "where is the moving thing right now?" For a person walking around, every old sighting is a wrong answer; the permanent memory returns the smear of all of them, the decayed one returns only the freshest — and admits "forgotten" when even that has gone stale. Furniture keeps its permanent map either way.

Setting λ = 1 turns M_now back into an ordinary permanent memory: decay is a dial, and your original associative memory sits at one end of it.

Time appears two entirely different ways: as an addressable coordinate (FPE ctx_time, bound into the event trace — query any moment, nothing fades) and as an amplitude fade (λ in M_now — no coordinate, just recency). They are complementary: the logbook and the whiteboard.

2 · The λ decay, precisely

M_now ← λclass · M_now + conf · ( CLASS ⊗ POS(x, y) )

  • What λ multiplies: the whole existing trace — every stored (class ⊗ place) pair fades together as a unit. It is not attached to the time code or the position code; there is no ctx_time inside M_now at all. Time enters only through when each event was written.
  • Per class: person λ = 0.9 (forgets in ~70 stale frames), furniture λ = 0.995 (nearly permanent). Implemented as separate per-class accumulators bundled at query time.
  • Provenance: proposed 2026-07-29 in the dynamic-objects design discussion (the neuroscience-flavoured long-term vs working-memory split; in engineering terms, an exponential moving average — trivial in VSA because bundles are linear). Implemented 2026-07-30 (build_now/query_now); added to the demo as the "now" mode the same day.
  • Two traps found during implementation (both worth remembering):
    • Mass imbalance: a rare class (person, trace mass ~223) is undecodable from a raw bundle shared with heavy classes (chair ~17,000) — crosstalk dragged the person peak 3.09 m. Fix: normalize each class trace by its own decayed evidence mass.
    • Normalization cancels decay: trace and evidence both shrink by λk, so their ratio preserves the last field forever. An evidence floor (10⁻³) restores true forgetting — below it the memory reports "forgotten" instead of a stale answer.
  • Measured: fresh sightings decode 0.12–0.51 m from truth; after 150 stale frames weight ≈ 2×10⁻⁷ → flagged forgotten (similarity 0.13 vs 0.77–0.93 fresh). The static memory, asked the same question, answers identically at all times with the all-sightings smear.

Hybrid decay clocks — what does "stale" count? (new, Jul 30)

build_now --decay-per {event, frame, metre, both} picks the clock the fade runs on. Each class's clock counts from its last write (frame row + cumulative robot travel):

λ_eff = λ_time ^ Δt_frames × λ_dist ^ Δd_metres

  • event (default) — decay per written event; verified bit-identical to the previous build.
  • frame — decay per elapsed frame: a paused robot still forgets.
  • metre — decay per metre travelled (--lambda-static-dist 0.999, --lambda-dynamic-dist 0.7 per metre; 1/e washout = −1/ln λ metres): a paused robot keeps its memory. Distance-knob credit: Krausse's le-marmotte 1/e washout — independently convergent; the product form composes both.
  • both — the product of the two. Caveat: a product of decays is AND-forgetting — the memory fades if either clock advances — not an interpolation between them.
  • Measured contrast (compare_clocks, real stationary window in the walk — person stale 75 frames at t=1163 while the robot barely moved): metre keeps weight 14.8 while event/frame/both collapse to <10⁻³ ("forgotten"). At a moving window (t=551, 2.06 m travelled) all time clocks give w≈0.03, metre w=28. Trade-off: metre slightly smears fresh fields. Figure: outputs/classroom/decay_clocks_comparison.png.
  • Mode + rates are stored in memory_now.pt meta, so query_now knows which clock built the memory.

3 · The code map — every file, in dependency order

Core algebra

vsa_cognitive_mapping/vsa.pyported Jul 14

The FHRR phasor core ported from the Telluride repo (jepa branch): Phasor (unit-modulus complex vectors; bind = elementwise ×, unbind = ÷, bundle = mean, FPE = fractional powers for continuous values), random_project_to_phasor (real features → phasors), analysis helpers (correlation matrices, fidelity/orthogonality scores, PCA). 18/18 upstream tests pass; one-line py3.9 compat change only.

Perception → memory pipelines

classroom_pipeline.pyJul 14 → extended Jul 29–30

embed (YOLOv8n over the Spot classroom walk → per-frame features + detections) · build (per-axis position/heading/time memories + the semantic memories; PCA whitening on by default — raw YOLO features have 0.88 mutual cosine and 365× coherent crosstalk; whitening is what makes everything decode) · evaluate (self-recall in metres/radians/frames: 0.14 m / 0.13 rad / 3.7 fr) · demo (gif) · query_class, query_event (conditional what/where/when) · new: --place-mode object (bind to depth-derived object positions — chair peaks land 0.13–0.34 m from independently clustered furniture) · new: build_now/query_now (the λ working memory, §2) · new Jul 30: build_now --decay-per {event|frame|metre|both} + --lambda-{static,dynamic}-dist (which clock forgetting runs on, §2) and compare_clocks (all four clocks on the same data → one figure).

object_map.pyJul 14

The constructive object map: lifts every detection to a metric world position (box + median D455 depth + pose), clusters into 83 discrete objects, binds CLASS ⊗ POS(x,y) into one vector, and serves an interactive map (class → heatmap of object locations; click → ranked "what's here"). This was the first "where ARE the items" memory — --place-mode object later brought the same idea into the main pipeline.

The ASTM engine (the paper's core)

astm_traces.pyJul 29 → upgraded Jul 30

The multi-trace spatio-temporal memory: a canonical event stream (4,498 events) feeds four permanent traces — three marginals + the full what⊗where⊗when event trace ("VSA secondary indexes": never store more factors than a query can supply; violating this costs a measured 22× attenuation). Plus: closed-form time-range kernels (a time window costs the same as a time point; probe-side only), a query router (give any two of what/where/when, decode the third), which-moved vocabulary scans, an exact event table baseline that auto-scores every answer, and — new — multi-scale time (bundle/bind of 5/20/80-row kernels; honest result: neither dominates, mode-picking is the real error source) and calibrated abstention (null-distribution z-scores; z≥3 ≙ sim≈0.0037; 93% confident-correct, 80% abstention precision). Range queries: 168 → 14.5 ms after the fast-decode rewrite. Jul-30 additions: export --place-mode object (depth-localized events, 2.1% fallback — ASTM chair peak 0.086 m from the largest furniture cluster vs 2.11 m vantage) with hygiene filters --min-class-events/--class-blocklist at the canonical-stream boundary; build --class-weighting {conf|balanced|log} — the sqrt-N frequency bias appears as position error (rare-tercile 5.15 m under conf) and log weighting fixes it (0.12 m, frequent classes unharmed); bench --bias-bench (tercile bias benchmark); --events-name/--traces-name for parallel event streams / trace sets.

calibration_eval.pyJul 30

Proper calibration metrics on a 544-query labeled battery (435 answerable, 109 unanswerable): AUROC z 0.872 vs raw sim 0.878 — per decode type they tie by construction (z is a monotone affine of sim within a type), so the z-score's value is the interpretable threshold, not extra discrimination; ECE ≈ 0.067, Brier ≈ 0.14; risk–coverage: z≥3 gives 42% coverage at 29% selective risk (vs 62% error at full coverage). Key finding: range-kernel queries need shape-matched nulls — the stored point-probe null does not transfer.

moved_object_synthetic.pyJul 30

The "which object moved?" claim, tested by construction: relocate all 265 second-half tv events by 1.68 m, then run gated which_moved (min-sim from a fake-class range-matched null). Modified run: tv ranks #1, displacement measured 1.71 m vs 1.68 m injected; control run clean (0.38 m vs 0.24 m natural). Bonus lesson: the timeless marginal is bimodal and its argmax loses the old place — the time-bound event trace is necessary.

language_query.pyJul 30

Language→VSA queries: MiniLM sentence latents, whitened over a ~180-noun vocabulary (isotropy medicine for the language modality), projected to phasors; memory rebuilt with text-derived class atoms over object-position events. On 15 never-stored paraphrases: soft grounding (text-sim routing) 10/15 top-1, median 0.11 m; direct latent unbinding (free text as the unbinding key, no codebook) median 0.17 m, 12/15 within 1 m. Failures are LM-semantic ("something to sit on"), not VSA-mechanical; the two mechanisms fail on different queries.

astm_sweep.pyJul 30

The D×N evaluation matrix: 5 dimensions × 4 event counts × 3 seeds = 60 cells in 7.7 min. Findings: accuracy saturates from D=4096 (0.70→0.87 across D); no capacity cliff at full 4,498 events; Pareto knee = D=4096 (118 MB honest total state, 0.80 accuracy, 2.7 ms median query); calibration improves with D (0.84→0.94 confident-correct). CSVs + 4 figures under outputs/classroom/sweep/.

Science probes

probe_jepa_predictability.pyJul 30

The VSA-JEPA go/no-go measurement: FPE transport is exact (cos = 1.0000), so bound-state prediction reduces identically to content persistence (0.727 ≫ null 0.015). Conclusion: a learned predictor must beat persistence, not the null — i.e. model how appearance changes with motion; the algebra already does the rest for free.

online_whitening_eval.pyJul 30

Closes the "whitening is offline" gap with numbers: causal streaming Welford whitening (per-frame top-64 eigendecomposition, sign-aligned) matches oracle isotropy by t≈300 and reaches near-oracle recall by the final third (0.146 vs 0.090 m grid-decode L1). A frozen calibration lap does not suffice at any K (1.15–1.73 m); EMA is worse than exact Welford everywhere. Surprise finding → design law: causal codes stay ~orthogonal to final-stats re-encodings (sim 0.29 even late) because degenerate eigen-subspaces keep rotating — store codes as encoded; never re-encode stored content. (Eval only — the deployment flag in the pipeline is still open.)
