Results briefing · for a SLAM & semantic-mapping audience · 2026-07-30

A queryable spatial–semantic–temporal memory in fixed-size vectors

TL;DR — key results
  • Loop closure: episodic memory built from loop-1 frames recalls loop-2 revisit positions at median 0.08 m (shuffled-content null: 4.35 m). (log p)
  • Semantic mapping: "where are the chairs?" peak lands 0.086 m from the largest detector-derived object cluster. (log n)
  • Language: free-text sentence embeddings, used directly as unbinding keys, localize never-stored paraphrases at median 0.17 m. (log o)
  • Calibrated self-doubt: abstention AUROC 0.905 vs raw similarity 0.875; bench 15/16 confident answers correct, 4/4 abstentions genuinely wrong (100% abstention precision). (log s)
  • The enabling fix: PCA whitening of learned features buys a ~22× interference reduction; heading recall 28% → 98%. (log t)
  • Honesty: an exact event table beats this memory on raw accuracy and lookup latency at demonstrated scale (full-state byte crossover ~2.7 M events) — the claim is the capability set, not database economics. (log t)

1 · What this is

We built a robot memory that stores every detection a Boston Dynamics Spot made during a classroom walk-through — what it saw, where, and when — inside a handful of fixed-size vectors (8,192 complex numbers each), and answers spatial-memory questions by algebra instead of database lookup. Place recognition, semantic object queries, "where was X at time t", change detection, decaying working memory for dynamic objects, free-text language queries, and calibrated self-doubt all run against the same vectors, in milliseconds, on CPU, on real Spot RGB-D + LIO-SAM data (2,478 frames).

Why care: unlike a scene-graph or landmark database, the trace state does not grow with experience — 4,498 events occupy the same 256 KB as 500; the full map state (118 MB at D=4096) is dominated by decoder grids and codebooks, which scale with vocabulary and query resolution, not event count — queries are single vector operations, and the memory reports a calibrated confidence, including an honest "I don't know." Every number on this page has been reproduced from a logged command by an independent verification pass (see the provenance note at the end); the honesty sections state plainly where a plain database still wins.

2 · How it works in plain terms

Everything is one representation: a vector of 8,192 unit-length complex numbers — think of a strip of tape holding 8,192 tiny clock hands, each frozen at some angle. Three operations do all the work.

Bind (⊗) — glue two things into one

In plain terms Like stacking two tinted transparencies: the stack resembles neither sheet — it looks like noise — but nothing is lost.
(a ⊗ b)k = e i(θk + φk) Add the clock angles position by position. Binds "chair" to "at (3.2, 1.4)" into a single vector that resembles neither factor. The binding is exactly invertible; recovery from a superposition is approximate.

Bundle (Σ) — record many onto one

In plain terms A multiple-exposure photograph: many recordings on one strip of film. The strip never gets longer; each recording just gets slightly noisier as more go in.
M = Σi ai ⊗ bi The vector stays the same size no matter how many items go in. Recall signal-to-noise scales as √(2D/K) for K items in D dimensions (the factor 2 from the real-part readout) — the capacity trade measured in §5.

Unbind (⊘) — ask the memory a question

In plain terms Hold the exact complementary filter up to the stack: whatever was bound with that factor snaps back into focus, while every other recording stays incoherent noise.
M ⊘ a = M ⊗ a−1 Subtract the angles of a factor you know. For unit-modulus phasors the inverse is exact — which is why the content vectors are normalized onto the unit circle.

The robot's whole event log — every (class, place, time) detection — is superimposed into one such vector, with continuous position and time encoded by fractional power encoding so nearby places get similar vectors:

Mevent = Σi confi · Ci ⊗ S(xi) ⊗ T(ti) The whole event log — every (class, place, time) detection — superimposed in one fixed-size vector. Continuous position and time are encoded by fractional power encoding, so nearby places get similar vectors.
"where was the chair at t?" → decode  Mevent ⊘ (Cchair ⊗ T(t))  over an (x, y) grid One unbind, one similarity sweep: 8–11 cm answers in milliseconds. Ambiguity shows up as a multi-modal heatmap instead of hiding behind an argmax.

Why four traces, not one

In plain terms Like secondary indexes on a database table: same data, one copy per query shape, so each question hits the layout that answers it best. Writes fan out ×4, which is trivial.

One measured design rule shapes the architecture: unbinding a triple-bound trace with only one known factor attenuates the answer 22× (0.247 vs 0.011). So the system keeps four traces — class⊗place, class⊗time, place⊗time, and the full event trace — one per query shape. Marginal questions use the high-SNR marginal traces; only fully conditional questions touch the event trace. (log b; evidence table)

What the loop-closure experiment actually did

The single classroom walk was split into a pseudo-second loop by frame interleaving, giving the memory genuine revisit structure with positions unchanged. A memory built only from loop-1 frames was then asked to localize loop-2 frames it had never stored: median error 0.08 m, and the shuffled-content null (4.35 m) shows the recall is driven by what the robot saw, not by any grid artifact. The same memory, asked "when was I at this place?", correctly returns both visit times as a bimodal decode — the honest answer for a revisited spot.

What the language experiment actually did

Free-text phrases the robot never stored — "cold storage for food", "luggage", "cutting tool for paper" — were embedded with a sentence model, whitened with the same isotropy treatment as the visual features, and used directly as unbinding keys against the memory. No class lookup, no prompt engineering: the text vector itself is the query key, and it composes with time and place like any other atom. Failures are language-model-semantic (genuinely ambiguous phrases), not memory-mechanical.

What the introspection battery actually did

A 544-query labeled battery mixed answerable questions with genuinely unanswerable ones (things never seen, times outside the run). Each answer's raw similarity is converted to a z-score against a null distribution matched to that query's trace and probe shape — point, range, or marginal. That matching is what makes the confidence informative: the shared-null version added nothing over raw similarity, the shape-matched version discriminates (AUROC 0.905 vs 0.875) and, on the bench, abstains only on answers that were in fact wrong.

4 · The load-bearing discovery: isotropy

In plain terms Imagine every photo of the room looking 88% identical to every other photo. Stack hundreds of such near-identical transparencies and you get a uniform grey blur: the shared component reinforces itself in lockstep while the distinctive detail drowns. Whitening subtracts what all frames share and re-stretches what remains, so each frame becomes distinctive again — and the memory starts working.

The single most transferable lesson for anyone bolting learned features onto an associative memory: raw CNN embeddings are not ready for superposition. YOLOv8 frame features on this data have pairwise cosine similarity 0.76–1.00 (mean 0.88) and effective rank 8 of 256 — every frame "looks like" every other frame. Bundle hundreds of them and the shared component adds coherently: measured interference grows linearly with the number of stored items (fitted log-log slope 0.97 over N=50→1,239) and recall collapses. PCA whitening (subtract the mean, decorrelate, equalize variance) buys a ~22× interference reduction at every N (85× → 3.8× in per-item-signal units at the full stream) — a constant-factor win, not a scaling-law change: residual real scene correlations (whitened mean |cos| ≈ 0.07) keep growth near-linear (slope 0.86), which is exactly why learned isotropic encoders remain the next rung. Outcome: effective rank 8→64, heading recall 28% → 98%. Prior VSA lineages used random atoms that are isotropic by construction, and learned-embedding anisotropy — with whitening as the fix — is established for language embeddings (Mu & Viswanath 2018; Ethayarajh 2019; Su et al. 2021) and for learned HRR vectors (Ganesan et al. 2021); see §7b for the full positioning. The new part here is the quantified anisotropy → associative-recall-collapse link on a deployed robot, plus a causal online estimator of the whitening statistics. (evidence table; demo explainer)

Deployment version, measured: online causal whitening (streaming Welford mean/covariance) matches oracle-level isotropy by frame ≈300 and reaches near-oracle recall by the final third of the run (0.15 m vs oracle 0.09 m grid-decode L1). A frozen calibration lap does not suffice at any length (1.15–1.73 m), and EMA estimates are worse everywhere. One design law fell out: store codes as encoded — never re-encode stored content. Codes written under early statistics stay nearly orthogonal (sim 0.29) to re-encodings under final statistics, because degenerate eigen-subspaces keep rotating. (log k)

5 · Capacity and cost

In plain terms Doubling the vector size buys accuracy at a diminishing rate, and stuffing 9× more events into the same memory degrades it gently rather than hitting a wall. A plain database is still faster and more exact at these scales — what it cannot do is compose what/where/when in one algebraic operation, take free text as a query key, or tell you how confident it is.

A 60-cell sweep over dimension D ∈ 1024–16384 and stream length N ∈ 500–4498 (3 seeds, 15-query battery, 7.7 min total) maps the trade-space. Accuracy climbs 0.70 → 0.87 with D and saturates past D=4096 (+0.03 per doubling). There is no capacity cliff at the full 4,498-event stream: the smallest memory (D=1024) degrades only mildly (0.78 → 0.67) and D=16384 is best at full stream (0.91). The Pareto knee is D=4096: 0.80 battery accuracy, 2.7 ms median query, 118 MB honest map state — "honest" meaning it counts everything, including the precomputed decoder grids that dominate; the traces themselves are 256 KB. Confidence quality also scales: confident-correct rate climbs 0.84 → 0.94 with D. (log j)

The honesty note — with the crossover computed. At 4,500 events an exact event table (measured 79 B/event; indexed lookup 1.8 µs) beats this memory on raw accuracy and latency — as predicted, and it is baseline A in every benchmark run. The measured economics: the traces (256 KB, event-independent) already out-size the table beyond ~3,300 events; the full map state (dominated by decoder grids and codebooks, which scale with vocabulary and resolution, not events) wins on bytes only beyond ~2.7 M events, and an indexed table is never beaten on raw lookup latency at feasible scales (log t). The claim is therefore not economics against a database — it is the capability set no table has: conditional what/where/when in a single algebraic operation, free-text latents as query keys, calibrated self-doubt, and bounded trace growth with graceful (measured, not cliff-edge) degradation. (evidence table; working doc Q6)

6 · Known limits, stated plainly

Everything above is measured; the following is what is not yet.
  • Position scaling needs our own staged collection with surveyed ground truth — required, not optional. The larger school_run1 dataset's own LIO-SAM odometry is diverged at km scale (~30 m building, pose spans of hundreds to thousands of metres, 209 jumps > 5 m, longest clean segment 4–10 s); heading/time scaling numbers survive, position does not. (log h)
  • Comparison baselines B–D are unrun. Only baseline A (exact event table) exists; the deterministic temporal graph, LLM-as-query-compiler, and generative VLM baselines — plus ReMEmbR — are the biggest gap between what is measured and the paper's position. (evidence table)
  • The two-loop result is a machinery test, not a robustness result. The second loop is synthesized by frame interleaving — interleaved frames are ~0.1 s apart with near-identical appearance. It proves the revisit algebra works; real multi-loop data with viewpoint and lighting change has not been collected. (log p)
  • One room, one platform. The physical data is a single classroom loop (~7×6.5 m); place≈time confounds are only broken synthetically. (limitations ledger)
  • Approximate extrinsics. The camera extrinsic is approximated and object placement is not survey-grade, so centimetre-level numbers carry that floor. (classroom results ledger)
  • Also open: loop-closure re-anchoring of an already-written map, persistent instance identity (needs a tracker front-end), multimodal-time mode-picking (the dominant residual decode error), and wiring online whitening into the deployment pipeline. (working doc)

7 · Related work — where this sits

7a · VSA foundations and capacity theory

The algebra is Plate's Holographic Reduced Representations [1] in their complex (FHRR) form, part of the broader hyperdimensional-computing family [2] surveyed comprehensively by Kleyko et al. [6] and compared architecture-by-architecture by Schlegel, Neubert & Protzel [7]. The capacity behaviour we lean on — how many items a bundle holds before recall degrades, including decaying traces as a working-memory mechanism — was worked out theoretically by Frady, Kleyko & Sommer [3], with sharper bounds from Thomas, Dasgupta & Rosing [4] and Clarkson, Ubaru & Yang [5]. All of that theory assumes random, near-orthogonal atoms. Our contribution is empirical and downstream of it: measuring what happens when real learned perception features violate that assumption on a deployed robot — and what restores the theory's predictions (§4).

7b · Embedding anisotropy and whitening

That learned embeddings are anisotropic — dominated by a shared mean direction and a few strong components — is well established for language representations: Mu & Viswanath's all-but-the-top post-processing [8], Ethayarajh's geometry analysis of contextual embeddings [9], and Su et al.'s whitening for retrieval [10]. Closest to us, Ganesan et al. [11] showed learned vectors destabilize HRR training and fixed it with a projection step. The established results concern retrieval quality and HRR numerical stability; the new link here is to bundled-superposition capacity, measured end-to-end on robot data — the anisotropy → coherent-interference → recall-collapse chain of §4. Our own N-sweep also shows whitening is a constant-factor fix, not a scaling-law change (residual scene correlations keep interference growth near-linear, slope 0.86), which is precisely what motivates learned isotropic encoders as open work rather than declaring the problem solved.

7c · Language-queryable maps

The open-vocabulary mapping family — VLMaps [12], CLIP-Fields [13], NLMap-SayCan [14], LERF [15], OpenScene [16], and ConceptFusion [17] — established that robots can answer free-text "where is X?" queries by storing visual-language features in the map and scoring text embeddings against them. Structurally, all of these keep a per-cell, per-point, or per-field feature store that grows with the mapped area or point count, and answer a text query by a dot-product sweep over that store. Our memory differs on both axes: the store is fixed-size, and the text key composes algebraically with time and place in a single unbind — "where was the cold storage at time t in window [a,b]" is one operation, a query class none of these systems support because their feature fields have no temporal algebra. The honest counterpoint: their open-vocabulary perception is far richer than our detector-class world — they inherit full CLIP-scale vocabulary, we currently inherit 38 detected classes plus text-derived atoms.

7d · Spatio-temporal robot memory and scene graphs

The strongest contemporary alternatives store explicit structure. SuperMap [18] builds a real-time open-vocabulary 4D scene graph with persistent instance IDs and change detection (code unreleased as of writing); Khronos [19] formulates unified spatio-temporal metric-semantic SLAM in dynamic scenes; DynaMem [20] maintains an online dynamic spatio-semantic memory for mobile manipulation; and ReMEmbR [21] — our mandatory baseline — has an LLM reason over a long-horizon robot memory. The honest contest framing: these systems maintain exact, mutable, relational state — they win on exactness, instance identity persistence, and arbitrary relational queries. We maintain bounded, associative, approximate state — the claim is the algebraic query set (conditional what/where/when in one operation, closed-form time-range kernels), bounded trace growth with measured graceful degradation, and calibrated self-doubt. Which trade wins where is an empirical question; the planned baseline ladder (exact table → temporal graph → LLM-compiler → ReMEmbR) is designed to answer it rather than assume it.

7e · The in-house phasor lineages

This work deliberately unifies collaborating research lines that share the same phasor algebra. GC-VSA [22] introduced the what⊗where⊗when factorized event memory with resonator-based factorization, demonstrated on synthetic data — our multi-trace system is that idea run on real robot perception. VSA-OGM [23] applies the same vector family to occupancy grid mapping, reporting 400×/45× memory/latency gains over Bayesian Hilbert Maps on that task — those are their numbers on occupancy mapping, not ours. HyperSpace [24], a modular VSA spatial-encoding benchmark, independently reports cleanup/similarity search dominating runtime — matching our own finding that decode, not encode or unbind, dominates query latency. le-marmotte VGPI [25] is the complementary direction: lidar localization in one 2048-d vector (~16 KB map), 0.13 m one-shot SE(2) relocalization on this same Spot dataset family. Underneath all of it sits the Waterloo SSP lineage — fractional power encoding and spatial semantic pointers [26], spiking SSP-SLAM [27], recent SSP developments [29] — formalized as Vector Function Architectures by Frady et al. [28]. One substrate, four capabilities: GC-VSA queries, VSA-OGM occupies, VGPI localizes, init-am remembers. This work unifies the query thread with real perception.

One sentence to take away: a robot's semantic map, episodic memory, change log, and working memory can be operations in a single fixed-dimensional vector space — with bounded state, millisecond queries, calibrated confidence, and language access — and the condition that makes it work with real learned features is isotropy.
